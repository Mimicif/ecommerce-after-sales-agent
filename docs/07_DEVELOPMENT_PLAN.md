# 分阶段开发计划 v1.0

每阶段完成后更新PROJECT_STATUS.md，再进入下一阶段。以下是预估工作量，不是交付承诺；新手可能需要更多学习时间。
截至2026-10-13，M0–M6已验收；实际证据与当前运行方式见PROJECT_STATUS.md及16/17/18验收报告。M4首轮独立集失败保留，第二批新独立集达门槛；M6修复展示与checkpoint竞态后重新完整回归，不扩大原M4泛化成绩；自由文本语义限制见报告。

## M0：工程与环境（1–2个有效开发日）

建立Python工程、锁文件、配置、PostgreSQL迁移与种子导入。
验证Git、Python、Docker或已有PostgreSQL。安装遇到权限/凭据问题时记录具体阻碍，不擅自替换系统配置。
开发登录只在本地DEV_MODE开放，服务默认监听127.0.0.1。
创建健康接口与两个租户身份；工具不可依赖客户端伪造tenant。
完成条件：全新数据库能迁移/导入/重置；健康检查通过；种子隔离测试通过。
交付实际setup/run/test命令，不先开发前端。

## M1：确定性规则与只读业务（2–3日）

实现订单、物流、政策有效期、资格引擎、查单工具与schema。
把边界和隔离场景转成pytest；实现Clock注入。
完成条件：7天边界、特殊品类、旧政策、别人订单、无轨迹和查询失败均有真实测试。
任何LLM不可用情况下，业务规则仍可独立验证。

## M2：售后写入与模拟退款（3–5日）

实现draft、确认摘要、客户确认、提交、审核、仓库、退款job与模拟支付结果查询。
添加幂等记录、金额锁、版本冲突、活动case约束、审计。
先通过API/测试驱动完成全流程，不调用模型。
完成条件：普通退货和损坏审核流程跑通；重复提交/审批/支付、超时未知、成功后崩溃均不重复退款。
这是项目最重要的业务正确性阶段，不得以prompt代替校验。

## M3：接入单Agent（2–4日）

核验选定供应商SDK、model_id、工具调用能力与价格，锁版本。
建立LangGraph、checkpoint、有限工具、执行预算、澄清和等待确认。
实现run持久化worker及事件轮询。先使用工具fake做合同测试，再运行live模型。
完成条件：多轮查单→草稿→真实确认→提交，以及物流异常/转人工均有trace。
有fake测试但没有live调用时，显式记录部分完成。

## M4：政策检索与评测（3–5日）

实现条款索引、元数据授权过滤、引用，先测中文keyword基线。
有检索短板再加pgvector/混合检索；不为了简历先堆向量库和reranker。
实现36例规格的对应执行器，补至少24例独立验收样本。
完成B0/B1/B2适用子集对比、3次live重复、失败分类和成本/延迟报告。
完成条件：达到06_EVALUATION.md门槛，失败有证据与修复记录。
如果出现资金/权限问题先修后端守卫，不只改prompt。

## M5：前端与可讲述演示（2–4日）

客户聊天：消息、工具事件、引用、确认卡片和真实状态。
员工页面：待审队列、审核说明、收货、模拟退款流水和故障提示。
关键交互用独立角色session，不能一个万能用户同时绕过权限。
所有模拟支付明确标识；禁止将schema/内部prompt当主要产品内容。
完成条件：按11_DEMO_RESUME.md三个剧本现场操作，刷新/重复点击仍正确；主要页面可在普通笔记本使用。

## M6：交付（1–2日）

完善README真实启动说明、架构图、依赖锁、环境变量示例、可复现评测、已知限制与演示录屏。
从全新数据库和干净安装验证，再执行必要回归；没有新修改不反复无目的扩大测试。
默认交付本地项目；公网部署、真实集成另行定义。
完成条件：其他开发者按README跑通，同版本结果可追溯，全部MVP门槛已满足。

## 每个功能的小循环

一个用户故事 → 明确终态和不变量 → 写领域/API合同 → 最小实现 → 必要测试 → 一段真实trace → 更新交接。
不一次让编码助手生成整套系统；每次以一个阶段或一个可验收故事为单位。
