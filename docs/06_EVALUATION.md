# 评测与验收 v1.0

## 当前材料是什么

evals/scenarios.jsonl是36条场景规格，data/fixtures.json是基础环境。
M4已实现scripts/run_evals.py执行器、独立PostgreSQL schema和ASGI HTTP身份驱动、fault注入、评分器与报告；ASGI不是独立网络HTTP，另有本地服务冒烟。M1/M2领域和事务检查继续运行。
不允许将这36条都放进prompt few-shot，也不能按case_id硬编码答案。

request_contracts.json只补充可信用户动作和人工转接第二轮（ADR-017），评分器按expected字段通用判定，无case_id业务分支。B1只运行其中readonly_cases；规则/API标记SHARED并共享一次，S35标记FAULT_CONTRACT，不作为真实模型成绩。其他适用自然语言每基线三次LIVE；没有--live时只执行B0和确定性场景，不伪造Agent分数。

首批24条holdout_v1.jsonl由用户核验冻结（holdout_freeze.json），固定prompt-v4首轮B2成绩为27/33（81.8%），未达90%门槛。用户选择继续修复并新增独立样本；首批现为暴露回归集，原始失败保留在evals/reports/holdout_release，不再称独立泛化成绩。prompt-v5修复政策不可用时重复查询、条件式退款说明误拦截、具体订单资格核验遗漏。

第二批24条为holdout_v2.jsonl，人工核验文件为[HOLDOUT_V2_REVIEW.md](../evals/HOLDOUT_V2_REVIEW.md)。只有人工批准并写入holdout_v2_freeze.json后，--dataset holdout-v2 --live才允许执行；脚本校验数据哈希。第二批未用于prompt调优，API/领域合同核对与模型评测分开。B1子集来自样本readonly_comparison标记，只比较其只读问答。金额/日期/状态/引用以代码评分，可核查事实指标口径为结构化回复声明（包含可解析的失败尝试），另有有边界的文本检查，不能宣称衡量了全部自由文本事实。token/成本只含成功持久化的供应商usage；在usage前失败的调用仍可能计费，报告用量覆盖和价格区间，不声称账单精确值。

## 分层验证

L1：规则单元测试。时间边界、金额、状态、确认过期、品类与权限。
L2：真实PostgreSQL集成测试。并发重复提交、审批、流水唯一、崩溃恢复。
L3：工具合同。schema、错误码、身份注入和供应商失败。
L4：Agent端到端。自然语言、多轮澄清、工具选择、等待确认、引用。
L5：人工演示审查。客服能否理解摘要、状态、失败与下一步。

金额、授权、状态变化用代码判定；LLM judge仅辅助回答相关性和易读性。
不要要求唯一工具顺序：能以不同有效路径正确完成也应得分。必须执行的安全前提仍明确检查。
询问问题或转人工不一律算失败；场景expected规定正确终点。

## 场景执行

每例创建独立数据库schema或独立测试数据库，导入同一基础种子。
时钟固定为2026-10-11T10:00:00+08:00。
override_now、order_overrides、setup_steps和faults是执行器输入规格，必须实现相应adapter。
检查输入用户拥有的订单，只把自然语言和可见结果送给Agent；expected与hidden oracle不可进入模型上下文。
对审查、收货、确认等步骤，driver扮演相应独立身份，通过真实接口推进，不伪造数据库终态。
执行后读取DB/API状态、金额、引用和审计记录评分，保存失败trace。
错误注入包括请求前失败、支付成功但响应超时、本地落库前崩溃，不能统一模拟成抛异常就算覆盖。

## 数据分组与扩展

36例包含core、edge、security、reliability标签，作为开发回归集，规则/接口/Agent场景分别执行。
M4新增至少24例未用于prompt调优的独立验收集，包含不同订单金额/时间/表达、复合意图、否定与同类错误变体。
新增集由人工核验oracle，冻结版本。不能只把开发集换一个同义词后称独立验证。
每次将真实失败脱敏后加入回归；记录训练/调优暴露范围，避免以复用样本夸大泛化。

## 公平基线

B0：固定路由/表单工作流，拥有与Agent相同的业务API、权限和数据。
B1：LLM + RAG只读问答，供政策/事实问答子集对比。
B2：单Agent + RAG +工具 +确定性业务守卫。

完整任务完成率比较B0与B2；政策问答质量比较B1与B2。
B1没有写权限，不能用全业务任务的失败证明Agent优越。
三者使用相同数据、时钟、错误注入、预算口径；模型可比时使用同一模型。
报告回答“Agent在哪类不确定输入上有增益、付出了多少成本”，允许固定流程更好。

## 指标

| 指标 | 定义 |
|---|---|
| 任务成功率 | 达到场景预期业务终点且全部硬约束满足 / 所有适用任务 |
| 事实正确率 | 订单、物流、金额、政策等可核查断言正确数 / 可核查断言总数 |
| 违规操作 | 越权、缺确认提交、未审批退款、超额或重复退款的次数 |
| 澄清正确率 | 必要时澄清且不擅自选择对象的案例比例 |
| 转人工正确率 | expected要求转人工的例子中正确建单并说明原因的比例 |
| 检索覆盖 | 命中oracle要求条款的知识案例比例；policy引用必须存在且当前有效 |
| 延迟 | 活跃请求完成/正确暂停的时间，P50/P95；不包含人等数小时 |
| 成本 | 真实模型input/output token×当次价格 + 有收费的检索/工具调用 |
| 恢复成功率 | 注入故障后恢复至expected且不增加重复副作用的比例 |

每例至少运行3次live Agent，记录全部尝试；不能只取最好一次。
规则/接口确定性测试无需为凑次数重复调用LLM。
报告各子集分母、模型、预算、版本与置信范围；小样本不能等同生产可靠性。

## 本项目MVP门槛（设定值，不是大厂统一标准）

- 所有确定性权限、资金、确认和并发硬约束测试通过。
- 已定义的关键安全/资金场景每次零违规；这只是样本内检查，不是无限场景安全保证。
- 新增验收集业务任务成功率目标>=90%，不达标时保留错误分析且不能标记M6完成。
- 有效政策引用与可核查事实正确率目标>=95%。
- 同一模拟支付operation重复执行不产生第二笔成功流水。
- Live模式P95目标<=30秒，单run硬截止45秒；报告供应商、网络与硬件，等待人工不计入。
- 至少提供一个完整基线对比及3类失败分析。
- 未连接live模型：只能完成offline checks，M3/M4 live验收保持未完成。
