# M1 只读业务与规则验收合同

日期：2026-10-12；实施前定义；不接模型、不写售后/工单/退款。

## 完成条件

1. 订单列表/详情、物流、政策、资格和工具复用同一服务端授权过滤，客户只能看自己的订单，客服只能看本租户订单。
2. 规则使用注入Clock；默认真实UTC，可通过可信开发配置选择fixture冻结时钟，HTTP和工具参数不能传now/tenant/actor/金额。
3. 常规退货验证7天含边界、超过1秒、未签收、缺失/未来签收、STANDARD/特殊品类、零元、全额与历史部分退款。
4. 损坏资格始终需人工审核，不把超过常规窗口视为损坏权利失效；描述/证据补充与正式提交属于M2。
5. 物流区分>48小时、=48小时、已标记异常、正常、无轨迹、未来轨迹与读取失败，不声称丢件/退款/已建单。
6. 只使用授权租户的PUBLISHED且effective_from<=now<effective_to政策；无版本/多个版本/缺条款/规则无效/发布内容漂移失败关闭。
7. 实现5个有限只读工具与JSON Schema：list_my_orders/get_order/get_logistics/search_policy/check_eligibility。枚举、额外字段、长度与分页均校验；工具结果含明确错误码。
8. pytest通过真实PostgreSQL迁移和隔离数据；M0回归通过；真实HTTP冒烟和Alembic一致性检查通过，保存脱敏证据并同步交接。

## 本阶段边界

`search_policy` 在M1只按租户、有效期和intent筛选并返回条款，不实现中文相关度检索；query通过schema校验但不参与排名。中文keyword基线与top-k评测在M4实现，不声称M1已完成RAG。
M1资格仅是当前订单/金额/政策的只读判断。数据库尚无case资源；M2必须在创建/提交/审批/执行时补活动case守卫及重新校验，M1不返回“无活动case”的虚假字段。
固定时钟只控制业务规则，session有效期仍使用真实UTC。全局安全约束来自领域代码（签收、品类、全人工审批、部分退款转人工等）；租户退货窗口来自结构化政策。
